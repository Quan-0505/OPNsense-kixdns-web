# Why version 0.1 "would not run", and what 0.2 changed

Every conclusion below was checked against the real sources, not guessed:

* `opnsense/core` master and stable/24.7, 25.1, 25.7 (MVC controller/model base classes, Router, ACL, the configd template engine)
* `opnsense/plugins` master (official plugin patterns such as ndp-proxy-go, the packaging rules in plugins.mk, and a real `os-*` package's `+MANIFEST`)
* `olicesx/kixdns` main (the clap CLI in `src/main.rs`, the config schema in `src/config.rs`)
* FreeBSD `usr.sbin/daemon` and `rc.subr` (the `-f`/`-S`/`-T`/`-P` semantics of daemon, rc.subr status matching)

## Defect list

| # | Location | Problem | Evidence | Fix |
| --- | --- | --- | --- | --- |
| 1 | Packaging `+POST_INSTALL` | The build workflow overwrote it with `exit 0`, so post-install did nothing: configd never learned the new actions and neither `/etc/rc.conf.d/kixdns` nor `/usr/local/etc/kixdns/pipeline.json` was ever generated | plugins.mk generates four steps (restart configd + run_migrations + rc.configure_plugins + template reload); a real `os-ndp-proxy-go` package's `+MANIFEST` `scripts.post-install` matches exactly | Embed the script in `+MANIFEST.scripts` (post-install / pre-deinstall / post-deinstall) with the official content |
| 2 | `ServiceController::reconfigureAction()` | Called `$this->sessionClose()` — a method that does **not exist** in `ApiControllerBase` on OPNsense 24.7/25.1/25.7/master, so clicking Apply always returned 500 | `ApiControllerBase` grepped in all four versions: zero hits | Remove the custom reconfigure entirely; let `ApiMutableServiceControllerBase` handle it (template reload + start/stop + status) |
| 3 | `SettingsController::getAction()` | `getBase('general','general')` ends up calling `$mdl->general->Add()`, but `Add()` exists only on ArrayField while `general` is a ContainerField — GET on the settings page returned 500 and the form stayed empty | The `$uuid == null` branch of core's `ApiMutableModelControllerBase::getBase()`; `ContainerField` has no `Add()` | Drop the custom get/set and use the base `getAction()`/`setAction()` (the `{kixdns: {...}}` shape); form field ids become `kixdns.general.*` |
| 4 | `SettingsController::setAction()` | `setBase('general','general')` omitted the required third argument `$uuid`, so PHP raised ArgumentCountError and saving always returned 500 | `setBase($post_field, $path, $uuid, $overlay = null)` | Same as #3 |
| 5 | Form ids | Field ids were `general.enabled` while the base getter returns `kixdns.general.enabled`; even with #3 fixed the data would not line up, and the same applied to the POST sent by `saveFormToEndpoint` | Compare with the official plugin's `ndpproxy.general.*` | Prefix every id with `kixdns.` |
| 6 | `rc.d/kixdns` start arguments | It started with `kixdns --config ... --listener-label ...`, but kixdns is a clap subcommand CLI that only parses `kixdns run --config ...`; without the subcommand every flag was discarded and the service ran on defaults (the relative path `config/pipeline.json` does not exist, so it crashed) | `main.rs`: `#[command(subcommand)] command: Option<Commands>` with all flags hanging off the `Run` subcommand | Start with `kixdns run --config ${kixdns_config} --listener-label ...` and pass the log level via `RUST_LOG` |
| 7 | How rc.conf.d was generated | The old code used PHP to `file_put_contents('/etc/rc.conf.d/kixdns')` as www — `/etc` is not writable, so it failed silently, `kixdns_enable` was never written, and rc.subr never started the service; it also only ran on "Apply", so the setting vanished after a reboot | OPNsense rc.subr behaviour plus every official plugin using configd templates (`xxx:/etc/rc.conf.d/xxx` in `+TARGETS`) | Add the template `OPNsense/KixDNS/kixdns → /etc/rc.conf.d/kixdns`, generated by configd as root |
| 8 | actions.d `[status]` | Missing `errors:no`. rc.subr exits 1 when the service is not running, and configd's `script_output` runs `subprocess.run(check=True)`, turning that non-zero exit into `"Execute error"` — status detection was completely broken | configd `script_output.py`: `check=not self.disable_errors`; compare with the official `actions_ndpproxy.conf` | Add `errors:no` to status (and to stop, where stopping an already-stopped service legitimately returns 1) |
| 9 | Pipeline editor Apply | The JS called `/api/kixdns/settings/reconfigure`, an action that does not exist (only the service controller has reconfigure) — Apply went down the wrong route | Routing: no reconfigure under the `settings` namespace; only ServiceController has one | Call `/api/kixdns/service/reconfigure` |
| 10 | Package ABI | `+MANIFEST` hard-coded `FreeBSD:14:amd64`. After OPNsense 26.7 moved to a FreeBSD 15 base, `pkg add` refused to install it | `https://pkg.opnsense.org/FreeBSD:14:amd64/26.7/` returns 404 while `FreeBSD:15:amd64/26.7/` returns 200 | The workflow emits packages from an ABI matrix (14/26.1 and 15/26.7, plus aarch64) with `opnsense-version` annotations |
| 11 | Missing ACL | No `models/OPNsense/KixDNS/ACL/ACL.xml`, so non-admin users could not be granted access through ACLs (admin has `page-all` and is unaffected, but the plugin was non-conformant) | Official plugin directory layout | Add the ACL (ui/api kixdns plus the log page) |
| 12 | No log sink | The binary only wrote to stdout/stderr and daemon discards those to /dev/null by default, leaving no readable log | With no SSH there was nothing to diagnose | `daemon -S -T kixdns` plus a local syslog-ng filter `kixdns.conf` writing to `/var/log/kixdns/`, with a Log File menu entry |
| 13 | No version marker | `/usr/local/opnsense/version/kixdns-community` was never installed, so the Firmware page did not recognise the plugin | The official install step writes that file | Write it while staging in the workflow |
| 14 | `rc.d` variable `kixdns_program` | The name collides with FreeBSD rc.subr's `${name}_program` mechanism (`_rc_namevarlist` contains `program`), so rc.subr treated it as a per-service command override: `/usr/sbin/daemon` was discarded and `kixdns -f -S ...` was executed instead, making kixdns report `unexpected argument '-f'` | **Reproduced on a real OPNsense 26.7 box** (`sh -x` trace shows `_doit` starting with kixdns instead of daemon) and the `_rc_namevarlist` definition in the FreeBSD 15 rc.subr source | Rename it to `kixdns_bin` and add a regression assertion to check_plugin.py |

## Things left unchanged on purpose

* **Defaulting to port 5353 instead of 53** is intentional. When you need 53, disable Unbound and change the bind address in the pipeline editor.
* **`kixdns reload` is equivalent to restart**: kixdns has its own file watcher, but it does not handle changes such as the bind address, so reload is conservatively implemented as restart.
* **`general.log_level` now actually works**: it is passed as `RUST_LOG` (tracing's EnvFilter takes precedence over `--debug`) rather than being decorative.
